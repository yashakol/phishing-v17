# Протокол воспроизводимости V17

## Объект воспроизведения

Цель - получить конкретный отправленный `submission_content_v17.csv` с SHA256 из `delivery_config.json`. Прогноз рассчитывается моделью на всех 16000 строках; эталон CSV читается для сравнения после расчета. Эталонные ответы не входят в обучение или признаки.

Все входы находятся в этом репозитории. `delivery_assets.py` проверяет размеры и SHA256 отдельных частей и собранных файлов. Копии восстанавливаются в `.runtime/`. `SOURCE_SNAPSHOT.json` контролирует неизменность исторических исходников. `payload/manifest.json` раскрывает каждое логическое имя, размер и контрольную сумму входа.

## Установка окружения

Для этой поставки созданы два отдельных новых окружения решений без доступа к системным site-packages. Зависимости скачаны из PyPI в общий кеш wheels, затем действительно установлены в пустые `.venv`. Старое окружение исходного проекта не использовалось для вычислений этих проверок. Подтверждение загрузки библиотек из нового `.venv`, версии, платформа и аппаратная конфигурация записаны в `verification/environment_setup.json`.

Проверенная установка выполнялась командой `reproduce.py setup --wheelhouse PATH`. Обычный `setup` устанавливает те же закрепленные версии через pip. Интернет нужен только для получения зависимостей. Для расчета ответов и обучения внешние сервисы не вызываются.

## Полный прогноз

Команда `python3.12 reproduce.py` восстанавливает артефакты, проверяет исходники, загружает модель V17 и согласованные кеши URL/HTML. Кеши test не содержат меток; порядок URL во всех входах сравнивается с `test.csv`. После расчета проверяются заголовок, последовательность Id, бинарность классов, число строк, SHA256 и полное совпадение с файлом исходной отправки.

Отчет: `verification/predict.json`, журнал: `verification/predict.log`. Все 37 закрепленных версий сверяются во время выполнения. В обученном ансамбле нет таблицы опубликованных меток test.

## Точный объем повторного обучения

V17 - финальное обучение специалиста поверх зафиксированного ансамбля предыдущих собственных стадий. Определение этого решения включает следующие обучающие входы:

1. Уже обученные базовые компоненты из `artifacts/v17/ensemble.joblib`.
2. Зафиксированную матрицу `reports/v17/full_training_frame.npz`, 7119 строк и 354 признака.
3. URL и собственные метки этих строк в `data/v17_training_rows.csv`.
4. Параметры и области из сохраненных `preregistered.json` и `expert_fit.json`.

Логические пути здесь отсчитываются от `.runtime/`. До обучения проверяются SHA256 матрицы, протокола, параметры классификатора, индексы, метки, порядок URL/меток и соответствие сохраненному scope. Матрица содержит прежние OOF-признаки и признаки дополнительных собственных train-строк. Источники меток и прошлые ограничения оценки раскрыты в техническом описании.

`python3.12 reproduce.py train` создает новый CatBoostClassifier с 800 итерациями, глубиной 5, learning_rate 0.04, регуляризацией 30, seed 20261010 и двумя потоками. Он обучается на 7119 строках. Вероятности на всех этих строках сравниваются с исходным компонентом на точное совпадение. Затем компонент включается в ансамбль, ансамбль сохраняется и загружается заново, рассчитывается весь test и проверяется исходный SHA256 CSV.

Отчет: `verification/train.json`, журнал: `verification/train.log`. Базовые компоненты в этом шаге сохраняются. Историческое обучение всех ранних словарей, SVM, бустингов и правил от сырого HTML этим шагом не повторяется; их исходники и обученные веса предоставлены. Поэтому термин "повторное обучение V17" здесь относится к точно определенной финальной стадии, а не к заново выполненному поиску всех предыдущих версий.

## Границы проверки

Проверен исходный конкретный CSV и воспроизводимость финального обучения в указанном окружении. Новая независимая оценка F1 не измеряется: прежняя диагностическая часть уже вошла в финальное обучение. Приватный результат неизвестен. Численная идентичность обучения на других ОС или архитектурах отдельно не подтверждена; при согласовании условий можно использовать проверенную платформу.

## Изменение упаковки для передачи

После проверок модели часть еще не переданных файлов `payload/parts/` дополнительно разделена на куски до 2 MiB из-за сетевых тайм-аутов. Уже принятые GitHub части сохранены. Полные байты и SHA256 всех логических входов остались прежними; данные и модель не менялись. Проверка: [payload_repartition.json](../verification/payload_repartition.json). Поэтому число частей в исторических `predict.json` и `train.json` относится к упаковке на момент тех запусков. Восстановление текущей упаковки отдельно проверено в `git_checkout.json`.
